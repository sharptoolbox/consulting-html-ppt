横向分类 vs 纵向分列 —— 一句话判断

两把尺子：子条目数量 × 单条字数
每类的子条目 单条字数 用哪个模板 骨架
横向分类 少（每类 1–3 条） 多（每条 2–4 行、≥ 30 字） 23（+ 结论带 → 27） 2–4 列并列，每列一块"宽"栏
纵向分列 多（每类 4–8 条） 少（每条 ≤ 14 字、单行） 24（+ 分组框 → 25） 2–4 列，每列一个"高"清单
都不极端 每类 3–5 条 中（每条 ≤ 20 字） 25 分组框（2×2） 独立描边框聚合
扁而多 每类 2–4 条（每条 1 行） 少（每条 ≤ 18 字） 26 类目行式（横向滑） 类目在左、右侧 只 1 列（不得再分列）
两者都是 2–4 个类目；类目数为 2 时可把列宽放大 1 倍（更舒展）。区别只在"每类条目多少 × 单条字多字少"： 条目少而字多 → 横向分类（宽列吃长文本）；条目多而字少 → 纵向分列（高列吃多条短条目）。判断失误会让页面要么右半空、要么文字挤成豆腐块。
26 的单列铁律：类目行式里右侧永远只有 1 个框、1 列条目（示例放 2 行）；条目变多时加高行高、减少类目数，绝不在右侧再切 2–3 个子列（那会退化成 23）。行高 = 380 ÷ 行数 − 20。
投放口径（决定是否真正"铺满 + 居中"）： ① 保留图底说明行 → viewBox="0 0 1200 447"，通栏 1880×700 正好铺满； ② 删掉图底说明行（实际投放建议）→ viewBox 高度改为内容下沿：23/24/25/26 用 0 0 1200 380（得 1880×595）、27 用 0 0 1200 404（含结论带，得 1880×633），再在剩余空间内上下左右居中； ③ 公式：投放高度 = 1880 × viewBox高 ÷ 1200（viewBox 宽恒为 1200）。类目数为 2 时也可整体投右栏 1120×700（等比 0.933）。

横向分类布局（少类目 · 长文本）

每类子条目少、单条文字多 / 观点陈述 / 判断依据 / 无法图形化 通栏 1880×700

类目行式清单（左类目 + 右侧单列条目）

类目扁而多 / 右侧 1 列 · 每框 2 行条目 / 最省竖向空间 通栏 1880×700
最适合"类目扁而多、单条话不多"的清单（如四类来源 × 各 2–4 条）。类目横过来放在左侧，比分列式更省竖向空间。 右侧硬性只有 1 列：每行右侧是 1 个整框，框内条目自上而下排成 1 列（示例放 2 行，标为参考数据）。不得再把右侧切成 2–3 个子列——一旦分列，行式"逐行读数"的节奏就断了，视觉上也和 23 横向分类撞车。 线 + 框三重奏：① 左类目色块（实心框）② 右条目框（描边框，每行仅此一个）③ 行间横线（分隔线）；框内每行条目前置 2.5px 类目色短横线（长 14）。 条目更多怎么办：不要分列，改为减少类目数 + 加高行高——行高 = 380 ÷ 行数 − 20；4 行 → 80（2 条）、3 行 → 106（3 条）、2 行 → 170（5 条）。始终 1 列。 投放：通栏 1880×700（等比 1.567），整体上下左右居中。实际投放建议删掉图底说明行：viewBox 高度改为内容下沿 —— 23/24/25/26 用 0 0 1200 380（1880×595）；27 含结论带用 0 0 1200 404（1880×633）；随后在容器内上下左右居中。
